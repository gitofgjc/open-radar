# GitHub Radar 产品设计

## 目标

构建一个个人长期使用的 GitHub 开源工具雷达：每天给出可快速阅读的简报，同时保留可检索、可筛选、可收藏的仓库资料库。首版必须在没有专用服务器的情况下运行，并能在 GitHub Pages 上稳定发布。

## 信息架构

- **今日**：值得试、增长最快、Stars 总榜、今日变化和抓取状态。
- **探索**：仓库搜索、主题/语言/许可证/活跃度筛选、排序和分页。
- **项目详情**：项目简介、Stars/forks、24h/7d/30d 趋势、维护信号、许可证、README 摘要、入选理由。
- **我的清单**：本地收藏、标签、状态（想试/评估中/使用中/已归档）、备注。
- **数据说明**：数据来源、最后抓取时间、统计窗口、API 状态、历史数据积累情况。

## 数据口径

- 数据源为 GitHub REST API；前端只读构建时生成的 JSON，不在浏览器暴露 token。
- 仓库元数据与每日快照分离；增长值由真实快照差值计算。
- Stars 总榜明确标注观测范围和抓取时间。
- 增长榜展示 1d/7d/30d 绝对增量与相对增速；至少两个有效快照后才显示窗口增量。
- 冷启动期间显示“趋势积累中”，不填充虚构的零值。
- “值得试”展示可见理由：近期 push/release、文档/README、许可证、社区信号和主题匹配，不输出不可解释的总分。
- 抓取失败保留最后一次成功数据，并显示 stale 状态。

## 本地体验

收藏、标签、状态和备注保存在浏览器 localStorage，首版无需 GitHub OAuth。导出/导入 JSON 作为设置页功能，便于迁移。

## 更新与部署

GitHub Actions 在 UTC 00:17（北京时间 08:17 附近）每日执行，也支持手动触发。抓取脚本使用 GITHUB_TOKEN，读取 rate-limit 响应头，限制候选数量并在失败时保留上次数据。生成静态站点后用 GitHub Pages 发布。第一次推送需要用户对目标仓库有 push 权限，但不需要把密码或 token 提供给代理。

## 质量要求

响应式桌面优先，移动端可浏览；所有数据卡片显示更新时间或来源；外部文本必须转义；无数据、限流和历史不足均有明确状态。前端交互以原生 JS 实现，避免不必要的运行时依赖，保证 Pages 部署简单。
